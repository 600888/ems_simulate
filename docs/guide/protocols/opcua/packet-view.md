# OPC UA 报文与诊断查看

OPC UA 的通信排查使用 **会话与通信日志** 页，记录实际服务调用的摘要。当前未实现原始 UA TCP 二进制报文抓包，因此本页展示会话和服务日志，适用于浏览、读写、订阅和连接问题排查。

## 进入方式

1. 选择 OPC UA 设备，启动服务端或客户端连接。
2. 执行浏览、读取、写入或订阅，让设备产生真实通信。
3. 进入 **会话与通信日志**，点击 **查询** 刷新记录。
4. 按服务名称过滤记录，或导出 CSV。

## 会话与服务调用

| 字段 | 用途 |
|------|------|
| 会话 / Application URI | 识别连接及客户端应用 |
| 用户、状态、原因、时间 | 查看会话建立、关闭或失败情况 |
| 服务 | 区分 Browse、Read、Write 等实际调用 |
| NodeId | 定位操作的目标节点 |
| StatusCode | 判断调用结果及权限、节点或类型错误 |
| 耗时 / ms | 观察调用响应时间 |

诊断摘要不记录凭据或变量值；字节收发统计目前不提供。

## 常见排查

- **连接失败**：确认服务端已启动，Endpoint URL 的 IP、端口和路径一致；在运行状态页查看错误。
- **节点不存在**：先浏览远端地址空间，核对 NodeId 与命名空间，不要直接沿用其他设备的命名空间索引。
- **写入失败**：核对变量的可写权限、值类型、用户角色和模拟规则的外部写入策略。
- **订阅没有数据**：确认节点为 Variable，监控模式为 Reporting，订阅已启用，再检查质量码与重连状态。
- **历史查询失败**：确认服务端已对该变量启用历史记录，查询范围内有数据；聚合读取需要远端支持。
