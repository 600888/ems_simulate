# 桌面端后端动态端口改造

## 背景

桌面应用的后端曾固定监听 `8991`，当该端口被其他程序占用时后端无法启动。
旧的停止逻辑还会按端口查找并终止进程，存在误伤其他程序的风险。

## 方案

桌面应用启动时分配一个 `50000-65535` 范围内的回环端口：

1. 使用当前时间和进程 ID 生成随机起始位置。
2. 从该位置循环探测 `127.0.0.1` 上的可用端口，已占用端口自动跳过。
3. Tauri 将选定端口通过 `--port` 传给 Python sidecar。
4. 加载页通过 `get_backend_url` 获取本实例的真实地址，不依赖固定端口。
5. 健康检查、状态检测和重启均读取本实例保存的端口。
6. 重启复用原端口，保证当前 WebView 的 origin 不发生变化。
7. 停止时只终止当前实例持有的子进程句柄，不再按端口扫描和杀进程。

普通 MSI/Linux 模式和 MSIX 模式共用同一套端口分配器。

应用通过 Tauri 单实例插件保证同一时间只有一个桌面实例。再次启动应用不会创建新的
后端进程，而是显示、恢复并聚焦已经运行的主窗口。单实例插件在所有其他插件之前
注册，确保第二个进程在进入 `setup`、访问共享数据目录或拉起 sidecar 之前退出。

## 边界

- 动态端口只用于桌面壳拉起的 Web 后端；直接运行 `start_back_end.py` 时仍可通过
  `--port` 显式指定端口。
- 应用数据目录由唯一实例独占使用，不支持同时运行多个桌面实例。
- 仿真设备自身监听的 Modbus、IEC 104、IEC 61850 等业务端口不在本次改造范围内，
  同一台机器上仍不能由不同实例重复占用同一个业务端口。

## 验证

- 单元测试确认动态端口位于 `50000-65535`。
- 单元测试确认端口被占用时会选择后续可用端口。
- Rust 后端模块测试通过。
