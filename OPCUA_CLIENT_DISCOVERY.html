OPC UA 客户端自动发现 ​

目标与范围 ​

现有客户端支持单层 Browse 和安全页 GetEndpoints，但缺少递归发现远端变量及批量配置采集的入口。本次增加客户端「发布订阅 → 实时数据 → 自动发现变量」，基于已连接会话发现可读变量，选择后加入当前订阅草稿。

实施计划 ​

  1. 抽取现有 Browse/BrowseNext 引用读取，复用 continuation 的释放、单层数量限制和请求次数限制。
  2. 实现广度优先递归发现：NodeId 去重、循环保护、深度限制、10000 个访问节点上限、最多 1000 个变量及 1–60 秒超时；局部读取失败返回详情，根节点失败明确报错。
  3. 从远端读取 NodeClass、名称、DataType、AccessLevel、UserAccessLevel、ValueRank 和 NamespaceArray；只返回有读取权限的变量，携带命名空间 URI。
  4. 新增 POST /api/opcua/nodes/discover，限定已连接的 OPC UA 客户端；返回结果、访问数量、失败节点及截断原因。
  5. 增加中英文发现对话框，支持起始 NodeId、最大深度、数量、超时和标准节点开关，展示可选择结果与失败详情。
  6. 合并当前订阅草稿，按命名空间 URI + 标识符去重，兼容未配置 URI 的已有监控项，保留现有采样参数。通过原有保存/开始订阅流程持久化及创建监控项。
  7. 验证真实 UA 嵌套节点、环、多重引用、读取权限、订阅通知、分页释放、断开连接、参数限制，以及前端草稿合并和异步状态失效。

使用方式 ​

启动 OPC UA 客户端后，进入发布订阅的实时数据页面，点击自动发现变量。默认从 i=85（Objects）开始，深度 16、最多 1000 个变量、30 秒。默认跳过 Server 诊断分支及标准命名空间变量；标准文件夹仍可遍历。

勾选变量后点击加入订阅草稿，再保存配置或开始订阅。发现与草稿添加不修改本地四遥测点表、不自动启用订阅。结果不完整时展示原因，可缩小起始节点范围重试；重新执行不会重复加入监控项。

本次范围不含网段扫描、LDS/mDNS 服务器发现和连接时自动重扫。已有 Endpoint 发现入口继续可用。

SDK 参考：asyncua Node API。

验证结果 ​

  • OPC UA 协议及通道配置回归：110 通过，1 跳过（仓库既有条件跳过）。
  • 最终发现测试：7 通过，覆盖真实会话与数据通知、循环去重、权限、深度、变量数、访问数、超时、取消、参数校验及连接变化。
  • 前端订阅与选择测试：21 通过，覆盖草稿添加、URI 去重、重复发现、保留采样设置及断开后拒绝添加。
  • Vue/TypeScript 类型检查、Ruff 检查及修改文件格式检查通过。
