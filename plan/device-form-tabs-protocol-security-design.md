# 设备新增/编辑分 Tab 设计

## 1. 文档信息

- 状态：待评审
- 适用范围：设备新增、设备编辑对话框
- 关联前端：`front/src/components/device/AddDeviceDialog.vue`
- 关联后端：`src/web/api/channel/router.py`、`src/data/model/channel.py`、`src/web/api/channel/helpers.py`

## 2. 需求定义

设备新增和编辑对话框调整为三个 Tab：

1. `基本信息`：当前对话框已有的全部内容原样保留在这里。
2. `协议参数`：只配置协议运行时行为，例如连接超时、单条命令超时、重试次数和重连间隔。
3. `加密配置`：配置是否启用 TLS，并上传证书和私钥。

本次调整的核心原则是：**现有表单内容不拆分、不换位置、不改变业务含义；第二个 Tab 只承载新增的协议运行参数。**

## 3. 现状

当前 `AddDeviceDialog.vue` 内按以下顺序展示：

1. `DeviceFormBasic.vue`
   - 设备编码
   - 设备名称
   - 设备分组
2. `DeviceFormConfig.vue`
   - 通信介质
   - 连接模式
   - 通信协议
   - IP、端口
   - 串口号、波特率、数据位、停止位、校验位
   - DL/T 645 电表地址
3. `DeviceFormPoints.vue`
   - 普通协议 Excel 点表导入
   - IEC 61850 服务端 ICD/SCD/CID/XML 模型导入
   - IEC 61850 客户端提示

上述内容及其条件显示、默认值、文件选择、ICD 预览和提交顺序均属于已有功能。

当前协议运行参数多数硬编码在运行时：

- Modbus TCP 客户端默认超时 3 秒、重试 1 次，部分单次读写外层又分别硬编码 1 秒或 2 秒。
- Modbus 客户端断线重连采用指数退避，上限 30 秒。
- IEC 104 客户端连接等待超时默认 3 秒。
- DL/T 645 客户端默认超时 3 秒，服务端默认超时 30 秒。
- IEC 61850 客户端连接超时和 MMS 请求超时默认均为 3000ms，目前主要通过环境变量控制。
- IEC 61850 模型发现总超时默认 600 秒，心跳和重连参数存在硬编码。

因此第二个 Tab 的工作不仅是增加输入框，还需要把这些硬编码参数统一传到运行时。

## 4. 设计目标

### 4.1 必须实现

- 新增和编辑使用完全相同的三个 Tab。
- 第一个 Tab 保持当前表单内容、顺序和行为不变。
- 第二个 Tab 根据当前已选协议、连接模式动态展示适用的运行参数。
- 参数名称和单位统一，避免“超时”含义混乱。
- 所有参数有明确默认值、有效范围和运行时消费位置。
- 未填写新增协议参数时，运行行为与当前版本一致。
- 第三个 Tab 对网络连接提供“启用 TLS”开关，开启后显示“上传证书”和“上传私钥”。
- TLS 配置必须传递到对应协议运行时并实际参与连接或监听，不能只保存不生效。
- 密码、私钥口令等秘密不得明文落库、回显或写入日志。

### 4.2 不在本次范围

- 不移动现有 IP、端口、串口、连接模式、表地址和文件导入字段。
- 不改变现有协议类型与 `conn_type` 的映射。
- 不改变现有点表和 IEC 61850 模型导入流程。
- 不在本设计中增加公共地址、Unit ID、IED 名等非运行时参数；如后续需要，应另行评审放置位置。
- 不对串口连接提供 TLS；Modbus RTU、串口 DL/T 645 继续依赖物理链路安全。

## 5. 页面设计

### 5.1 对话框结构

```text
┌─────────────────────────────────────────────────────────┐
│ 添加设备 / 编辑设备                                ×    │
├─────────────────────────────────────────────────────────┤
│  基本信息            协议参数            加密配置       │
│  ───────                                                │
│                                                         │
│                    当前 Tab 内容                         │
│                                                         │
├─────────────────────────────────────────────────────────┤
│                                      取消   添加/保存    │
└─────────────────────────────────────────────────────────┘
```

- 对话框打开时默认选中 `基本信息`。
- 底部仍使用当前的“取消”和“确认添加/保存修改”，不改成分步向导。
- 保存时一次性校验并提交三个 Tab。
- 如果校验失败，自动切换到第一个存在错误的 Tab，并在对应 Tab 标题显示错误标记。
- 保存期间禁止切换 Tab、关闭对话框和重复提交，继续显示当前导入/重载进度。
- 建议宽度从当前 640px 调整为 720～760px，内容区超高时内部滚动。

### 5.2 第一个 Tab：基本信息

第一个 Tab 直接包含当前已有的三个子组件，不调整字段归属：

```vue
<el-tab-pane label="基本信息" name="basic">
  <DeviceFormBasic ... />
  <DeviceFormConfig ... />
  <DeviceFormPoints ... />
</el-tab-pane>
```

必须保持：

- 字段顺序不变。
- 当前协议与连接模式联动不变。
- IP、端口和串口配置仍在第一个 Tab。
- DL/T 645 电表地址仍在第一个 Tab。
- Excel 点表和 IEC 61850 模型导入仍在第一个 Tab。
- IEC 61850 ICD 预览按钮和预览对话框保持当前行为。
- 新增、编辑、导入、重载以及页面刷新流程暂不因分 Tab 而改变。

### 5.3 第二个 Tab：协议参数

此 Tab 只展示协议运行时参数。字段由第一个 Tab 当前选择的 `protocol_type` 和 `conn_type` 决定。

#### 参数术语

为避免不同模块含义不一致，统一使用以下术语：

| 参数 | 字段名 | 含义 |
| --- | --- | --- |
| 连接超时 | `connect_timeout_ms` | 客户端建立 TCP、串口会话或 MMS Association 的最大等待时间 |
| 单条命令超时 | `command_timeout_ms` | 一次读、写、控制或请求从发出到得到结果的最大等待时间 |
| 命令重试次数 | `command_retry_count` | 单条命令首次失败后的追加重试次数，不包含首次执行 |
| 重连初始间隔 | `reconnect_initial_interval_ms` | 连接断开后第一次自动重连前的等待时间 |
| 重连最大间隔 | `reconnect_max_interval_ms` | 指数退避时允许达到的最大等待时间 |
| 最大重连次数 | `reconnect_max_attempts` | 一轮自动重连最多尝试次数；0 表示持续重连 |
| 空闲连接检测间隔 | `health_check_interval_ms` | 检查连接是否仍健康的间隔 |

连接超时和单条命令超时必须分开，不能继续使用一个 `timeout` 同时表达两种含义。

#### 通用显示规则

- 客户端/主站显示连接、命令、重试和重连相关参数。
- 服务端/从站只显示实际有运行意义的参数；没有专用参数时显示“当前协议及连接模式暂无可配置的运行参数”。
- 所有时间输入在界面统一显示为毫秒；较长时间可以在输入框右侧同时显示换算后的秒数。
- 默认展示常用参数，高级参数放在“高级设置”折叠区。
- 每个字段提供“恢复默认值”，整个 Tab 提供“恢复本协议默认参数”。
- 切换协议或连接模式时，为每个组合保留当前对话框内的临时草稿，但只提交当前组合参数。

### 6.9 IEC 61850 客户端

| 分组 | 参数 | 默认值 | 建议范围 | 当前代码情况 |
| --- | --- | ---: | ---: | --- |
| 常用 | 连接超时 | 3000ms | 100～60000ms | 当前 `Iec61850Timeouts.connect_ms` 默认 3000ms |
| 常用 | 单条命令超时 | 3000ms | 100～120000ms | 对应 MMS request timeout，当前默认 3000ms |
| 常用 | 命令重试次数 | 0 | 0～5 | 写和控制默认不自动重试 |
| 高级 | 重连初始间隔 | 5000ms | 100～60000ms | 当前 `try_reconnect()` 默认 5 秒 |
| 高级 | 重连最大间隔 | 30000ms | 1000～300000ms | 当前指数退避未形成设备级配置 |
| 高级 | 最大重连次数 | 3 | 0～100 | 当前常用默认 3 次，不同调用点仍有差异 |
| 高级 | 空闲连接检测间隔 | 5000ms | 1000～600000ms | 当前硬编码 5 秒 |

## 7. 默认值与继承规则

### 7.1 兼容原则

- 新配置不存在时，使用上文列出的默认值，保证与当前硬编码行为尽量一致。
- 不在数据库中为所有旧设备立即写入默认记录，可在首次编辑保存时生成。
- 后端返回时必须给出合并后的有效值，前端不自行猜测默认值。

### 7.2 参数优先级

运行时读取顺序：

1. 设备级协议参数。
2. 后端协议注册表默认值。
3. 代码安全兜底值。

IEC 61850 当前环境变量只作为旧版兼容或进程级兜底。设备已经配置参数后，设备级值优先于环境变量，否则无法支持不同设备使用不同超时。

### 7.3 字段联动校验

- `command_timeout_ms >= 100`。
- `connect_timeout_ms >= 100`。
- `reconnect_max_interval_ms >= reconnect_initial_interval_ms`。
- `reconnect_max_attempts` 和 `command_retry_count` 必须为整数。
- 控制类协议的命令重试大于 0 时显示风险提示。
- `model_discovery_timeout_ms >= command_timeout_ms`。
- 不适用于当前协议/角色的字段不得提交或保存。

## 8. 加密配置 Tab

加密配置保持简单，只提供 TLS 开关、证书上传和私钥上传。

```text
加密配置
├── 启用 TLS        [开关]
└── 开启后显示
    ├── 证书        [上传证书]
    └── 私钥        [上传私钥]
```

交互规则：

- `启用 TLS` 默认关闭。
- 开启后，证书和私钥都为必填项。
- 证书支持 `.crt`、`.cer`、`.pem`。
- 私钥支持 `.key`、`.pem`。
- 每项只允许上传一个文件；重新选择即替换待保存文件。
- 编辑时显示当前证书和私钥的文件名及“已上传”状态，不回显文件内容。
- 后端校验证书与私钥是否匹配；不匹配时禁止保存。
- 关闭 TLS 时不启用证书和私钥，设备继续使用原有非 TLS 连接。
- 串口连接不显示 TLS 开关，只提示“串口模式不支持 TLS”。
- 第一阶段 TLS 运行时接入 Modbus TCP；其他协议显示“当前协议暂不支持 TLS”，后端同样拒绝开启，避免静默降级为明文连接。
- 修改 TLS、证书或私钥后，保存时重建设备协议实例，使配置实际生效。

证书和私钥随设备表单一起提交。新增设备时先创建通道，再把两个文件保存到该通道的受控目录；任一步骤失败都应向前端返回失败，不能显示保存成功。

安全要求：

- 不直接引用用户原始文件路径，避免源文件被移动或删除后设备无法启动。
- 私钥内容不得写入数据库、日志、异常详情或浏览器 `localStorage`。
- API 详情只返回证书、私钥是否已配置及文件名，不返回文件内容。
- 私钥文件应限制访问权限，不提供下载接口。

## 9. 前端实现设计

### 9.1 组件结构

```text
AddDeviceDialog.vue
├── Tab：基本信息
│   ├── DeviceFormBasic.vue       # 保持现状
│   ├── DeviceFormConfig.vue      # 保持现状
│   └── DeviceFormPoints.vue      # 保持现状
├── Tab：协议参数
│   └── DeviceProtocolParams.vue
│       ├── ProtocolCommonParams.vue
│       └── 各协议/角色参数区
└── Tab：加密配置
    └── DeviceSecurityConfig.vue
```

第一阶段不重写三个现有子组件，只在其外层增加 Tab 容器，降低回归风险。

### 9.2 表单模型

保持现有 `ChannelCreateRequest` 字段不变，只新增两个独立对象：

```ts
interface DeviceDialogForm extends ChannelCreateRequest {
  protocol_params: {
    schema_version: number;
    values: Record<string, number | boolean | string>;
  };
  security_config: {
    tls_enabled: boolean;
    certificate_configured: boolean;
    private_key_configured: boolean;
  };
}
```

`protocol_type`、`conn_type`、IP、端口和串口字段仍保留在原位置及原有请求结构中。

证书和私钥文件只保存在当前对话框内存中，不能进入 `localStorage`。

### 9.3 协议参数定义

前端不应在模板中散落大量 `v-if="protocol_type === ..."`。建议维护一个协议参数定义表，至少包含：

- 参数 key、标签、说明和单位。
- 支持的 `protocol_type + conn_type` 组合。
- 默认值、最小值、最大值和步进。
- 是否为高级参数。
- 风险提示。

后续可将定义表下沉为后端能力接口；第一阶段可先前后端共享一致的静态定义和测试用例。

## 10. 后端与数据模型

### 10.1 数据表

现有 `device`、`channel` 及其字段保持不变。新增协议运行参数表和 TLS 安全配置表：

#### `channel_protocol_params`

| 列 | 类型 | 约束 | 说明 |
| --- | --- | --- | --- |
| `channel_id` | Integer | PK、FK channel.id | 通道 ID |
| `protocol_type` | Integer | 非空 | 防止读取错误协议的旧参数 |
| `conn_type` | Integer | 非空 | 区分客户端/服务端或主站/从站参数 |
| `schema_version` | Integer | 非空 | 参数结构版本 |
| `params_json` | JSON/Text | 非空 | 只保存协议运行参数，不保存现有连接字段和秘密 |
| `created_at` | DateTime | 非空 | 创建时间 |
| `updated_at` | DateTime | 非空 | 更新时间 |

#### `channel_security_config`

| 列 | 类型 | 约束 | 说明 |
| --- | --- | --- | --- |
| `channel_id` | Integer | PK、FK channel.id | 通道 ID |
| `tls_enabled` | Boolean | 非空，默认 false | 是否启用 TLS |
| `certificate_path` | String(512) | 可空 | 应用受控目录内的证书路径 |
| `private_key_path` | String(512) | 可空 | 应用受控目录内的私钥路径 |
| `created_at` | DateTime | 非空 | 创建时间 |
| `updated_at` | DateTime | 非空 | 更新时间 |

数据库只保存受控文件路径，不保存证书或私钥正文。私钥文件必须限制访问权限。

### 10.2 后端模型

为每个有效协议/角色组合定义 Pydantic 模型，例如：

```py
class ModbusTcpClientParams(BaseModel):
    connect_timeout_ms: int = Field(3000, ge=100, le=60000)
    command_timeout_ms: int = Field(2000, ge=100, le=60000)
    command_retry_count: int = Field(1, ge=0, le=10)
    reconnect_initial_interval_ms: int = Field(2000, ge=100, le=60000)
    reconnect_max_interval_ms: int = Field(30000, ge=1000, le=300000)
    reconnect_max_attempts: int = Field(0, ge=0, le=100)
```

后端按 `protocol_type + conn_type` 选择模型，拒绝未知字段和不适用字段。

### 10.3 API 兼容

可以扩展现有创建、更新和详情接口：

```json
{
  "code": "PCS_01",
  "name": "1号PCS",
  "protocol_type": 1,
  "conn_type": 1,
  "ip": "192.168.1.10",
  "port": 502,
  "protocol_params": {
    "schema_version": 1,
    "values": {
      "connect_timeout_ms": 3000,
      "command_timeout_ms": 2000,
      "command_retry_count": 1,
      "reconnect_initial_interval_ms": 2000,
      "reconnect_max_interval_ms": 30000,
      "reconnect_max_attempts": 0
    }
  },
  "security_config": {
    "tls_enabled": true,
    "certificate_configured": true,
    "private_key_configured": true
  }
}
```

兼容规则：

- 请求没有 `protocol_params` 时按当前默认值运行。
- 详情接口始终返回合并默认值后的完整有效参数，方便编辑回显。
- 旧版前端仍可调用原接口，不受新增字段影响。
- 协议或连接模式改变时，旧参数记录不直接套用；保存当前组合的新默认值或新输入值。

证书和私钥上传接口：

```text
POST /api/channel/{channel_id}/security/upload
```

- 使用 `multipart/form-data`，字段为 `tls_enabled`、`certificate` 和 `private_key`。
- 新增设备在创建 channel 后调用；编辑设备只在 TLS 配置发生变化时调用。
- 上传成功后返回证书和私钥的文件名及配置状态，不返回文件内容或真实存储路径。

### 10.4 运行时传递

在 `Device._build_protocol_config()` 中新增统一结构：

```py
{
    # 现有字段保持不变
    "ip": self.ip,
    "port": self.port,
    "serial_port": self.serial_port,
    # 新增
    "runtime": {
        "connect_timeout_ms": 3000,
        "command_timeout_ms": 2000,
        "command_retry_count": 1,
        "reconnect_initial_interval_ms": 2000,
        "reconnect_max_interval_ms": 30000,
        "reconnect_max_attempts": 0
    }
}
```

各协议 Handler 只消费自己声明支持的参数。参数应在初始化时转换为底层库需要的秒或毫秒，内部统一保留毫秒，避免单位错误。

### 10.5 保存与重载

- device、channel 和 `channel_protocol_params` 应在同一数据库事务中保存。
- 编辑协议运行参数后需要重建客户端或服务端实例，确保底层库拿到新值。
- 保存前完成参数校验；运行时初始化失败时不得只记日志后返回成功。
- 第一阶段可沿用当前设备重载流程，但接口必须把重载失败明确返回给前端。

## 11. 实施计划

### Phase 1：Tab 外观与兼容骨架

- 在 `AddDeviceDialog.vue` 增加三个 Tab。
- 将当前三个表单组件完整放入第一个 Tab，不修改字段和提交行为。
- 新增协议参数组件，以及包含 TLS 开关和证书导入区域的加密配置组件。
- 完成 Tab 校验定位、禁用状态和样式。

### Phase 2：协议参数持久化

- 新增 `channel_protocol_params` 模型、DAO、Service 和启动迁移。
- 扩展请求/响应 Schema。
- 实现各协议/角色参数默认值与校验。
- 旧设备无配置时返回兼容默认值。

### Phase 3：运行时接入

- 优先接入 Modbus TCP/RTU 客户端，清理当前 1 秒、2 秒、3 秒的分散硬编码。
- 接入 IEC 104 客户端连接与命令超时。
- 接入 DL/T 645 客户端/服务端超时。
- 接入 IEC 61850 连接、MMS 请求、心跳、重连和模型发现总超时。
- 每接入一个字段都增加证明其实际生效的集成测试。

### Phase 4：安全配置

- 实现 TLS 开关、证书上传、私钥上传以及证书/私钥匹配校验。
- 实现安全配置表、受控证书目录和私钥访问权限控制。
- 为 Modbus TCP、IEC 104、DL/T 645 TCP 和 IEC 61850 分别接入 TLS 运行时适配器。
- TLS 配置应用失败时返回明确错误，不允许显示成功后仍使用明文连接。

## 12. 测试方案

### 12.1 第一个 Tab 回归

- 新增和编辑时现有字段、顺序、默认值和显隐规则不变。
- 五种协议的连接模式筛选不变。
- 网络和串口切换行为不变。
- Excel 点表导入、IEC 61850 模型导入及 ICD 预览不变。
- 原有保存、重载和成功回调行为不变。

### 12.2 协议参数测试

- 每个 `protocol_type + conn_type` 只显示适用字段。
- 默认值与当前运行行为一致。
- 范围和关联校验正确。
- 切换协议后不会把旧协议参数提交给新协议。
- 旧设备没有参数记录时正常加载默认值。
- 修改超时后，使用延迟响应测试证明运行时确实按新值超时。
- 修改重试次数后，通过断线/失败注入验证实际尝试次数。
- 外层异步等待不会早于用户配置的单条命令超时结束。

### 12.3 安全测试

- TLS 开关关闭时保持现有连接，开启时实际使用上传的证书和私钥建立 TLS 连接。
- `.crt/.cer/.pem` 证书和 `.key/.pem` 私钥可以正常上传。
- 缺少证书、缺少私钥或证书与私钥不匹配时禁止保存。
- 编辑时只显示文件名和配置状态，不回显或下载证书、私钥内容。
- API、日志和异常中不出现秘密原文。
- 删除设备时同步清理安全配置、证书和私钥文件。

## 13. 验收标准

- 新增和编辑设备均显示 `基本信息`、`协议参数`、`加密配置` 三个 Tab。
- 第一个 Tab 包含当前页面所有已有内容，字段归属、顺序、联动和导入功能不变。
- 第二个 Tab 只包含协议运行时参数，不重复 IP、端口、串口、地址、点表和模型字段。
- 不同协议和连接模式只显示真实适用且已接入运行时的参数。
- 连接超时与单条命令超时分别配置、分别生效。
- 未配置新增参数的旧设备保持当前运行行为。
- 网络连接可配置是否启用 TLS；开启后只显示“上传证书”和“上传私钥”两个文件项。
- TLS 配置保存后必须在对应协议运行时实际生效，握手失败不得静默回退到明文。
- 串口连接明确不提供 TLS 开关。
- 密码、私钥口令等秘密不明文落库、不回显、不写日志。
