# OPC UA 模拟、订阅、安全与历史实施记录

日期：2026-10-01。对应[开发计划](opcua-asyncio-development-plan.md)。这是 M2–M4 的增量交付记录，**尚未完成全部里程碑或生产发布验收**。

## 本次实现

- 独立 `simulation`、`subscriptions`、`history` 和 `events` 插件，使用通道自己的窄接口和任务。停机按注册表反向关闭，重连的旧回调按代际隔离。
- 固定、随机、正弦、步进模拟。用单调时钟确定相位；客户端写入支持暂停并保留、下周期覆盖、拒绝三种策略。可在运行中暂停/恢复模拟。节点规则仍需停止设备后保存。
- 真实 UA Subscription 和 MonitoredItem 创建，显示服务端返回的发布/采样间隔、队列、生命周期与保活计数；绝对死区、监控模式、逐项失败可见。运行中保存期望订阅配置会重建订阅，可通过启用开关暂停/恢复订阅，通过列表增删监控项。
- 客户端自动退避重连并重建订阅，按命名空间 URI 解析节点；事件订阅在新会话上恢复。客户端显式再次启动时先停止旧插件，避免与重连任务竞争。
- 通道独立、有界的实时事件出口，提供 WebSocket 和序号分页读取。慢消费方能检测缓冲丢失；趋势页使用真实通知，支持暂停、清空、CSV，遇到断线标记断开曲线。
- 扩展标量：Boolean、各有符号/无符号整数、Float/Double、String、DateTime、ByteString。64 位整数超出 JavaScript 安全范围时用 `{"integer":"..."}` 编码；二进制用 `{"base64":"..."}`，DateTime 要求时区并转换为 UTC。独立变量编辑器和客户端写入入口已适配这些类型。
- Endpoint 发现、应用证书生成、指纹审批/撤销、Basic256Sha256 Sign/SignAndEncrypt、用户名身份和查看/操作角色。未知对端证书拒绝连接并进入待审批列表；校验有效期、用途、Application URI、精确证书指纹，客户端额外校验主机名/IP。用户名身份要求 SignAndEncrypt。自定义会话观测器使用显式配置的用户管理器，禁止默认管理员身份绕过查看权限。
- 服务端监听地址与对外通告主机分离。NoSecurity 继续限制为 loopback；加密配置允许网络 Endpoint。更新 Endpoint 仍事务同步通道 IP/端口。
- 新 `opcua_feature` 表保存版本化期望配置，`opcua_secret` 表单独保存保护后的私钥/密码或加盐密码哈希。Windows 使用当前用户 DPAPI；POSIX 使用权限 0600 的 Fernet 密钥。普通配置不包含秘密，请求校验错误也移除输入值。复制设备复制期望配置和独立秘密记录，生成新应用证书/URI；对端需审批新证书。删除通道清理新增数据库记录。
- 服务端 SQLite 历史持久化、保留期和记录上限；客户端执行远端原始 HistoryRead，返回质量、UTC 时标、continuation，支持释放 token。SDK 2.0.1 的字符串 NodeId 表名带引号，被其 SQL 校验器拒绝；适配器用稳定 SHA-256 表名，并实现有界分页。历史重启后仍可查询。
- 基础事件生成、订阅、严重度筛选与事件列表；服务端页面可触发真实 UA 事件。当前事件视图消费有界实时流，未宣称是持久事件历史或完整条件告警。
- 用 SDK 的 InternalServer/Session 扩展点观测真实会话创建、激活、拒绝和关闭，记录实际 Browse/Read/Write/HistoryRead 调用与耗时。调用摘要只包含服务、节点、状态及会话，不保存读写值或凭据；保留 1000 条调用、100 条会话。不可观测的地址及字节统计返回空值。
- 设备页新增模拟/订阅、趋势、历史、事件、安全和通信日志入口，提供中英文文案。生产资源同步到 `www`，保留此前已有的资源文件。

## 数据与迁移

新增两张表由现有 `Base.metadata.create_all()` 在应用初始化时创建，没有改写旧四遥表及已有 UA 标量表。历史保存在数据目录下 `opcua/history-<channel_id>.sqlite`；POSIX 凭据密钥在同目录。设备复制不复制运行时 SubscriptionId、SessionId、事件流或历史采样。

升级前应备份数据库和 OPC UA 历史目录。Windows 凭据只能在保护它们的当前用户/机器上下文解密；迁移到另一用户/机器需重新配置私钥和客户端密码。回退旧版本须使用升级前备份；保留新表直接运行旧版并不是已经验证的回滚流程。当前尚未实现跨平台安装包升级/回滚验收。

## 手工验证入口

1. 建立 loopback 服务端并导入 27 点模板；在“模拟规则”添加数值节点规则，停止状态保存，启动后从客户端读写检查波形和写入策略。
2. 客户端“订阅管理”新增订阅与监控项，保存后启动；查看实际修订参数和“实时趋势”。停止/重启服务端，确认自动恢复及断线缺口。运行中可保存空订阅列表或关闭启用开关，确认不再接收该订阅的值。
3. 服务端“历史数据”选节点、保留天数与条数，停止状态保存。启动后写入不同值；客户端按 NodeId/时间范围查询、翻页。重启服务端再次查询旧值。
4. 两端生成各自应用证书，服务端添加用户。客户端发现服务端 Endpoint 并审批服务端证书；保存加密及用户名配置。第一次接入时服务端拒绝未知客户端证书，在服务端停止后审批该证书，再启动两端。查看用户读成功/写失败，操作用户写授权变量成功。
5. 两端启用基础事件，服务端触发事件；客户端核对真实通知。通信日志核对实际调用与当前/关闭会话。

## 仍需继续实现

- 完整对象、类型、引用和多命名空间建模；枚举、一维数组、结构体模型与对应编辑器；扩展 NodeSet XML 导入保真。当前独立变量可使用扩展标量，但 NodeSet 导入仍保留基础三种标量子集，不能将扩展变量导出再导入称为已验证往返。
- 客户端本地发现快照与模型加载/发现/导入/导出；受控批量/逐点轮询、工程量变换与反馈联动。
- 趋势多曲线、完整时间窗与浏览器背压验收；在线修改单个订阅目前通过整组重建实现，尚未对所有第三方服务器验证死区/模式的修订行为。
- 证书链/CRL 管理、完整证书生命周期和审计持久化、证书身份令牌、Linux 凭据与安全组合试验。现有信任是精确证书固定，不是完整 CA 信任库。

- 历史相同源时间戳的分页边界、异常写盘/保留期及大吞吐验收。当前 SDK continuation 以时间戳定位，同一时间戳多条记录边界尚需专项处理；删除通道后的历史文件清理/保留策略尚需统一。
- MQTT/JSON PubSub 发布器、数据集/元数据/事件 Writer、消息掩码、KeyFrameCount、队列与真实 broker 互操作。
- Windows/Linux 冻结产物、第三方互操作、长时资源释放、安全默认策略及全部 20 张画板走查。以上完成之前不能标记 M2–M6 全部完成。
